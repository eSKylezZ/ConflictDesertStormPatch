# DesertStormFix: the host layer and its plugins (DS1)

Since the plugin split (finished 2026-10-25) DesertStormFix is a small **host layer**, `PSE\Plugins\dsfix.dll`, plus 33
plugin DLLs in `PSE\Plugins` (32 on the dsfix kit and the external `dsfix.discord`). This page is the map for **porting
a feature to another Conflict game**:
- a feature's own code (RE addresses, hooks, game structures) is its plugin, in `games/ds1/plugins/<name>/`;
- what it needs of DesertStormFix is the host services below. The table at the end lists them per plugin. A port
  rebuilds those services in the other game's host plugin (ds2fix, cvfix, cgsfix, tgefix), or moves them into that game's
  PSE layer when they are game-neutral.

Per-plugin facts (flags, settings, hooks, what happens without it): [ds1-plugins.md](ds1-plugins.md). Loader and
layout: [layout.md](layout.md), [reference/plugins.md](reference/plugins.md).

## Layers, bottom up

| Layer | File | Owns |
| --- | --- | --- |
| shim | `<game>\dinput8.dll` (`pse/shim`) | the exe's entry point, loads the loader |
| loader | `PSE\pse_loader.dll` (`pse/loader`) | plugins, hooks broker, settings, co-save, events, crash guard, pse.ids / pse.lua / pse.vfs / pse.ui interfaces |
| game layer | `PSE\Games\pse_ds1.dll` (`pse/games/ds1`) | exe detection, the id database, the core events (frame, render, level, saves, D3D device, EndScene / Present, game events), co-save wiring, the original-files redirect, `pse.game.ds1` |
| host plugin | `PSE\Plugins\dsfix.dll` (`games/ds1/src`) | the host layer below |
| feature plugins | `PSE\Plugins\dsfix.<name>.dll` (`games/ds1/plugins/<name>`) | every feature |

A plugin works with the loader and game layer alone where it can (`dsfix.discord`: public SDK + `pse.game.ds1`
only). Everything else is on the **dsfix kit** (`plugins/kit`): `DSFIX_KIT_PLUGIN(name, display, flags, Load)`, the
broker-backed `core/patch.cpp`, `kit::DeclareBool` / `ImportFrom` for its own pse.settings key, and the generated
client of `dsfix.host`.

## What dsfix.dll keeps (the host layer)

Its internal plugins (`kFeatures`, `src/dllmain.cpp`) and the interfaces it publishes:

| Part | Where | What plugins get from it |
| --- | --- | --- |
| Settings | `core/settings.*` (pse.settings key `dsfix`) | DesertStormFix's own values (`DsfixSettingsValues`, services `DsfixSetting`, `settings::Save` / raw `ReadDword` / `WriteBinary` ...). A plugin's own toggles live in its own key (`kit::DeclareBool`) |
| `dsfix.host` | `src/core/dsfix_host.spec` -> `features/host_iface.cpp` | 165 plain-C calls into dsfix.dll, generated by `scripts/gen_host_calls.py`; a plugin's own functions are left out of its client (`plugins/<g>/generated/own_functions.h`) |
| `dsfix.services` v1 | `src/core/dsfix_services.h`, `features/services.cpp` | 30 members: text / screen / trigger-feel providers, settings listener, mod report, host values, mods data for older plugins |
| `dsfix.overlay` v1 | `src/core/dsfix_overlay.h`, `features/overlay.cpp` + `overlay_iface.cpp` | 27 members: icons, rects, lines, images, late draws, the game font. Drawn on the game layer's `PSE_EVENT_END_SCENE` (`dsfix.overlay`, first subscriber) |
| Menu framework | `fixmenu.cpp` (DESERTSTORMFIX), `frontend.cpp` (main menu items + the state -> screen router), `pluginsmenu.cpp` + `pseui.cpp` (`pse.ui`, PLUGINS) | plugins add screens / texts through the router and services providers; their rows show in DESERTSTORMFIX / PLUGINS |
| Text lookup | `ingame_input.cpp` (`Lookup`, the game's string lookup replaced) | plugins' texts by hash (services `SetTextProvider`, generated `...Text` wrappers), prompt icons |
| Frame dispatcher | `framecap.cpp` (frame cap at `0x4116EC`: wait, `OnFrameEarly`, the PSE frame), `launcher.cpp` `OnFrame` | each plugin's per-frame functions, called in a fixed order through its wrappers |
| Launcher | `launcher.cpp`, `launcher_pad.cpp` | the settings dialog, pad navigation, `+restart` wait (`dsfix.restart`) |
| Input helpers | `dev.cpp` (`KeyHeld`, `GameFocused`, posted keys in tests), `core/gamepad`, `ingame_input.cpp` (device in use, prompt style) | key / pad reading every menu-side plugin uses |
| Original files | `originals.cpp` (`dsfix.originals`) | `GameFile` / `GameFiles` / `OriginalPath`: the game's files in the game folder or `PSE\Originals` |
| Global Heap | `memory.cpp` (`dsfix.memory`) | the game's heap sized when the game creates it: + `dsfix.limits`' enlarged pools (they come out of it) + the largest mod file (`dsfix.mods`); texture / memory figures for the performance overlay. A host part because `dsfix.limits` needs it |
| Mod report | `modhost.cpp` | `ModLog` (log + `Mods\DesertStormFix-report.txt`), `BeginModReport`, `ModProblems`, `ModsFolderEnabled` |
| Diagnostics | `diagnostics.cpp`, `framerec.cpp`, `renderdiff.cpp` (dev) | the game's error boxes / debug print / file log, the performance overlay, the frame recorder (`framerec::Note` / `Now`) |
| Console | `console.cpp` | the developer console, `ConsoleStartLevel` (level starts for the online / video / mission plugins), PSE's shutdown at `WM_DESTROY` |
| Dev server | `devserver.cpp` (dev builds) | the live test pipe (`tests/live`) |

Rules that come with it:
- **Static CRT per DLL**: only plain C crosses (the generator refuses anything else); lists of structs cross as text
  rows (e.g. `ModGearRows`, `ModLevelRows`).
- **Defaults**: every function dsfix.dll calls in a plugin has an answer for "plugin missing" (`= value` in the
  plugin's spec). dsfix.dll code that runs before the plugins load must not need a plugin's answer.
- **Load order**: plugins load after dsfix.dll, by `requires` / `after`, then by name. Every DesertStormFix plugin has
  `after = dsfix.mods` (the Mods index, merged tables and mod files are ready before anyone asks).
- **Owners**: a hook a plugin makes belongs to that plugin (`pse_host::Find(...)` in kit code answers the plugin
  itself), so `dev.pse_hooks()` / crash reports name the DLL.
